# Clair V0.23

## Double boucle vérifiée une seule fois

Jusqu'ici, dans un produit de matrices, la boucle intérieure vérifiait ses bornes à chaque tour de
la boucle du milieu. Clair vérifie maintenant toute la double boucle d'un coup, avant d'y entrer :

```text
for k in range(n) {
    let aik: float = a[i * n + k]
    for j in range(n) {
        c[i * n + j] = c[i * n + j] + aik * b[k * n + j]
    }
}
```

devient

```c
if (clair_rt_affine_ok(a, i * n, 1, 0, n) &&
    clair_rt_affine2_ok(c, i * n, 0, 0, n, 1, 0, n) &&
    clair_rt_affine2_ok(b, 0, n, 0, n, 1, 0, n)) {
    double *clair_data_a = (double *)a->data;
    double *clair_data_c = (double *)c->data;
    double *clair_data_b = (double *)b->data;
    for (int64_t k = 0; k < n; k++) {
        double aik = clair_data_a[i * n + k];
        for (int64_t j = 0; j < n; j++) {
            clair_data_c[i * n + j] = clair_data_c[i * n + j] + aik * clair_data_b[k * n + j];
        }
    }
} else {
    /* même double boucle, vérifiée à chaque accès */
}
```

`clair_rt_affine2_ok(liste, c0, ck, k0, k1, cj, j0, j1)` vérifie que `c0 + ck*k + cj*j` reste dans
la liste pour tous les `k` de `k0` à `k1` et tous les `j` de `j0` à `j1`. Il suffit de regarder
les coins, avec contrôle de débordement. Cela marche aussi pour les matrices `m[i][j]`.

La double boucle est versionnée seulement si :

- la boucle intérieure est la seule boucle du corps, avec un pas de 1 ;
- ses bornes ne changent pas pendant la boucle extérieure (constante, variable non modifiée,
  `len()` d'une liste qui ne grandit pas, `rows()` / `cols()`) ;
- chaque indice est de la forme `c0 + ck*k + cj*j`.

Sinon, Clair garde la version V0.22 (vérification avant chaque boucle intérieure). Une erreur
d'indice s'arrête toujours au même moment, avec le même message.

## Option `--sans-verif`

```sh
./build/clair prog.cl -o prog --sans-verif
```

Pour les longs calculs déjà testés : le programme est compilé sans aucune vérification de bornes
sur les listes et les matrices, comme du C écrit à la main. La première ligne du C généré le dit :

```c
/* Generated by the Clair compiler (--sans-verif: no bounds checks). */
```

Attention : avec cette option, un indice faux n'est plus détecté. Le programme peut donner un
résultat faux ou planter. Il faut d'abord faire tourner le programme sans l'option. La division et
le modulo par zéro, eux, restent toujours vérifiés.

## Mesures

Sur PC (x86_64), `matmul` passe de +5 % à -2 % par rapport au C écrit à la main.

`matrice` reste à +8 % sur PC, même avec `--sans-verif`. L'écart ne vient donc plus des
vérifications : le vectoriseur x86 de Clang déroule la boucle intérieure 2 fois au lieu de 4. Sur
ARM64, l'assembleur de la boucle intérieure est le même que celui du C.

## Tests

  extérieure, indice non affine, `break` ;

- `--sans-verif` : même résultat que `loop_fast_path.cl`, aucune vérification dans le C, modulo
  par zéro toujours détecté.

800 programmes à doubles boucles tirés au hasard donnent exactement la même sortie qu'avec V0.22,
erreurs comprises.
